### **2. Контекст решения**

Данный раздел описывает окружение системы, ключевых пользователей и внешние системы, с которыми взаимодействует **AI Platform**.

#### **2.1. Контекст и границы системы**

**AI Platform** выступает в роли центрального координатора процессов машинного обучения. Она предоставляет интерфейсы для пользователей и интегрируется с критически важной инфраструктурой компании (безопасность, оркестрация, хранение, мониторинг).

На диаграмме ниже представлен высокоуровневый контекст системы и ее взаимодействие с внешними акторами и системами.

#### **2.2. Описание акторов**

| Актор                                                  | Описание                                                                                                     | Интерфейс взаимодействия             |
| :----------------------------------------------------- | :----------------------------------------------------------------------------------------------------------- | :----------------------------------- |
| **Конечный пользователь (Data Scientist/ML Engineer)** | Основной потребитель услуг платформы. Создает эксперименты, обучает и развертывает модели.                   | Веб-интерфейс (GUI), REST API        |
| **Системный администратор**                            | Управляет платформой: настройка, добавление предустановленных моделей в Model Garden, разрешение инцидентов. | REST API, Административный интерфейс |
| **Стороннее приложение/Сервис**                        | Внешняя система, потребляющая прогнозы от развернутых моделей в продакшене.                                  | REST API (Endpoint для инференса)    |


#### **2.3. Описание внешних систем**
*(Адаптируем под новые группы)*

| Внешняя система                                  | Роль и ответственность                                                                                                   | Тип взаимодействия                                                                                                  |
| :----------------------------------------------- | :----------------------------------------------------------------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------ |
| **Keycloak**                                     | Централизованный провайдер аутентификации и авторизации (IAM). Управляет пользователями, ролями и доступом.              | **Синхронное** (REST/HTTP). API Gateway вызывает Keycloak для валидации токенов OIDC.                               |
| **Kubernetes**                                   | Фундаментальная платформа для оркестрации контейнеров. Используется для запуска тренировочных jobs и сервисов инференса. | **Асинхронное/Синхронное**. Внутренние сервисы платформы взаимодействуют с Kubernetes API для управления ресурсами. |
| **S3-совместимое хранилище (MinIO)**             | Универсальное хранилище для всех артефактов: датасеты, веса моделей, логи тренировок, конфиги.                           | **Синхронное** (REST/HTTP). Сервисы платформы и обучающиеся контейнеры используют S3 API для чтения/записи.         |
| **Стек мониторинга (Prometheus, Grafana, Loki)** | Обеспечивает полную наблюдаемость: сбор метрик (Prometheus), визуализацию (Grafana) и centralized logging (Loki).        | **Асинхронное**. Сервисы платформы экспортируют метрики в Prometheus и логи в Loki.                                 |
| **GitOps (GitLab CI/CD & Flux 2)**               | Инфраструктура для автоматизации сборки, тестирования и развертывания самой платформы по методологии GitOps.             | **Асинхронное**. Изменения в Git-репозитории автоматически запускают процессы CI/CD и синхронизацию в кластере.     |
#### **2.4. Важные допущения**
1.  Перечисленные внешние системы (Keycloak, Kubernetes, S3) уже развернуты, настроены и доступны для использования платформой.
2.  Доступ к этим системам обладает достаточной надежностью и производительностью, чтобы не становиться узким местом для работы AI Platform.
3.  Администраторы внешних систем обеспечивают их поддержку и соответствие SLA.
