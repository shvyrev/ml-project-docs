### **4. Модель данных**

#### **4.1. Модель данных для Artifact Store**

Этот сервис отвечает за управление файлами моделей и других артефактов. Его основная цель — надёжное и эффективное хранение.

```mermaid
erDiagram
    UserEntity {
        UUID id PK "Идентификатор пользователя"
        String subject "ID из Keycloak"
        String username "Имя пользователя"
    }

    FileEntity {
        UUID id PK "Идентификатор файла"
        String etag "Контрольная сумма файла"
        long size "Размер файла"
        String storagePath "Путь в хранилище (MinIO)"
        String minioBucket "Название корзины MinIO"
        FileStatus status "Статус файла"
    }
    
    UploadSessionEntity {
        UUID id PK "Идентификатор сессии загрузки"
        String minioUploadId "ID многокомпонентной загрузки"
        long uploadOffset "Текущий сдвиг загрузки"
        long uploadLength "Ожидаемый размер загрузки"
        String originalFilename "Исходное имя файла"
        UploadStatus status "Статус сессии"
    }

    UserFileEntity {
        UUID user_id PK "ID пользователя"
        UUID file_id PK "ID файла"
        String originalName "Имя файла пользователя"
        String userPath "Путь пользователя"
    }

    UserEntity ||--o{ UserFileEntity : "имеет"
    FileEntity ||--o{ UserFileEntity : "принадлежит"
    UserEntity ||--o{ UploadSessionEntity : "создает"
    FileEntity ||--o{ UploadSessionEntity : "является частью"
```

  * **`UserEntity`**: Хранит основные данные о пользователе. Связь с `Keycloak` через поле `subject`.
  * **`FileEntity`**: Содержит метаданные о файле, такие как его физическое расположение, размер и статус. Это позволяет хранить один и тот же файл для нескольких пользователей, не дублируя его.
  * **`UploadSessionEntity`**: Используется для управления процессом загрузки файлов. Эта сущность делает возможным возобновление загрузки, что очень важно для больших файлов.
  * **`UserFileEntity`**: Связующая таблица между пользователями и файлами. Она позволяет одному файлу иметь несколько владельцев и хранит уникальные для каждого пользователя метаданные, такие как оригинальное имя файла.

#### **4.2. Модель данных для Model Registry**

Этот сервис управляет жизненным циклом моделей, их версиями и развертыванием.

```mermaid
erDiagram
    EndpointEntity {
        UUID endpointId PK "Идентификатор эндпоинта"
        String userId "ID пользователя"
        String name "Название"
        String description "Описание"
        ResourceStatus status "Статус эндпоинта"
        JSON labels "Метки"
    }

    ModelEntity {
        UUID modelId PK "Идентификатор модели"
        String userId "ID пользователя"
        String displayName "Название модели"
        ModelType modelType "Тип модели"
        JSON labels "Метки"
        String modelDescription "Описание"
        JSON inputSchema "Схема ввода"
        JSON outputSchema "Схема вывода"
    }

    ModelVersionEntity {
        UUID modelVersionId PK "Идентификатор версии"
        UUID modelId FK "ID модели"
        String userId "ID пользователя"
        String version "Номер версии"
        String artifactPath "Путь к файлу"
        ModelSourceType sourceType "Тип источника"
        ModelVersionStatus status "Статус версии"
        JSON labels "Метки"
        String description "Описание"
    }
    
    DeployedModel {
        UUID deployedModelId PK "Идентификатор развертывания"
        UUID endpointId FK "ID эндпоинта"
        UUID modelVersionId FK "ID версии модели"
        ResourceStatus status "Статус развертывания"
        int trafficPercentage "Процент трафика"
    }

    EndpointEntity ||--o{ DeployedModel : "использует"
    ModelVersionEntity ||--o{ DeployedModel : "развернута"
    ModelEntity ||--o{ ModelVersionEntity : "содержит"
```

  * **`ModelEntity`**: Представляет логическую модель. Она объединяет все версии одной модели.
  * **`ModelVersionEntity`**: Хранит метаданные каждой конкретной версии модели. Именно эта сущность привязана к физическому файлу (`artifactPath`).
  * **`EndpointEntity`**: Определяет эндпоинт, который служит точкой входа для инференс-запросов. Он содержит информацию о выделенных ресурсах.
  * **`DeployedModel`**: Связующая таблица, которая позволяет привязать одну или несколько версий модели к одному эндпоинту. Это делает возможными сценарии вроде **канареечных релизов**, когда трафик распределяется между разными версиями.
