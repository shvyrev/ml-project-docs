### **6. Варианты использования и сценарии**

В этом разделе мы подробно опишем два ключевых сценария, которые показывают, как пользователи будут взаимодействовать с нашей системой для загрузки и развертывания своих моделей.

#### **6.1. Сценарий: Загрузка файла с возобновлением**

Этот сценарий описывает процесс загрузки файла модели в сервис **Artifact Store**, используя механизм, похожий на **tus-протокол**, который поддерживает возобновление.

**Цель:** Пользователь хочет загрузить большой файл модели в систему.
**Действующие лица:** Пользователь, Фронтенд, Бэкенд (**Artifact Store**), Хранилище S3.

1.  **Инициализация:** Пользователь выбирает файл для загрузки на фронтенде. Фронтенд отправляет запрос на бэкенд для инициализации сессии. Бэкенд создает сессию и получает уникальный URL для загрузки напрямую в S3.
2.  **Частичная загрузка:** Фронтенд начинает загружать файл по частям (`chunks`) напрямую в S3, используя полученный URL. Это минимизирует нагрузку на бэкенд-сервис.
3.  **Возобновление:** Если соединение прерывается, фронтенд сохраняет информацию о прогрессе. Когда соединение восстанавливается, он снова обращается к бэкенду за новым URL, но уже для возобновления загрузки, указывая, с какого байта нужно продолжить. Система S3 позволяет продолжить загрузку с того места, где она остановилась.
4.  **Завершение:** Когда все части загружены, фронтенд отправляет финальный запрос, подтверждающий завершение, и получает уведомление об успешной загрузке.


#### **6.2. Сценарий: Развёртывание модели на эндпоинт**

Этот сценарий описывает процесс развёртывания уже зарегистрированной модели на эндпоинт, который будет готов принимать запросы на инференс.

**Цель:** Пользователь хочет запустить свою модель в продакшене.
**Действующие лица:** Пользователь, Фронтенд, Бэкенд (**Model Registry**), Kubernetes, NVIDIA Triton Runtime, Хранилище S3.

1.  **Создание эндпоинта:** Пользователь через фронтенд создает новый эндпоинт, указывая его название и другие параметры. **Model Registry** создает соответствующую запись в базе данных и отправляет команду в Kubernetes для создания "пустого" объекта `ClusterServing`.
2.  **Развёртывание версии:** Пользователь выбирает конкретную версию модели, которую он хочет развернуть на этот эндпоинт. Он предоставляет системе информацию о модели, версии и желаемые ресурсы (CPU/RAM).
3.  **Создание Inferenceservice:** **Model Registry** отправляет в Kubernetes команду на создание объекта `Inferenceservice`. Этот объект содержит всю необходимую информацию для **NVIDIA Triton**, включая путь к файлу модели в S3.
4.  **Загрузка модели:** Kubernetes запускает один или несколько подов с **NVIDIA Triton Runtime**. Тритон самостоятельно обращается в S3-хранилище и загружает указанную модель.
5.  **Готовность к инференсу:** Когда модель успешно загружена, Тритон сообщает об этом Kubernetes. Kubernetes обновляет статус `Inferenceservice` на "Готов".
6.  **Уведомление:** **Model Registry** постоянно мониторит статус `Inferenceservice` через **информеры** и, как только получает информацию о готовности, сообщает об этом на фронтенд. Пользователь получает уведомление и URI для инференс-запросов.
